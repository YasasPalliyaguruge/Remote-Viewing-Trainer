# Aetherium Sensory-Description Trainer

![Aetherium remote-viewing trainer cover](assets/recruiter/cover.png)

Aetherium is a browser-based practice application for comparing a user's free-form sensory impressions with a hidden, AI-generated target description. It guides the user through onboarding, target configuration, a self-paced note-taking session, target reveal, and an AI-assisted text comparison.

The interface is inspired by remote-viewing exercises, but the application does not claim to measure paranormal ability, scientific accuracy, statistical significance, or predictive performance.

## Implemented workflow

1. Complete the introductory onboarding.
2. Choose a description-complexity level and target category.
3. Start the implemented self-paced solo exercise.
4. Gemini generates a target description that remains hidden in the visible interface.
5. Record up to 5,000 characters of sensory or conceptual impressions.
6. Reveal the target and compare both descriptions.
7. Review AI-generated heuristic scores and transparent attribute matches.

## Feedback model

The feedback screen presents three explicitly heuristic values:

- **Descriptive similarity** — estimated overlap between the two texts
- **Evidence specificity** — how specific and supportable the identified overlaps appear
- **Distinctiveness estimate** — whether the overlaps appear distinctive rather than generic

These are generated by a language model. They are not laboratory measurements, p-values, statistical tests, proof of a phenomenon, or validated measures of user ability.

## Technology

- React 19 and TypeScript
- Vite
- Framer Motion
- Google Gen AI SDK
- Structured Gemini JSON responses for the feedback comparison

## Local setup

Install the exact dependency tree recorded in `package-lock.json`:

```bash
npm ci
```

Copy the environment template:

```bash
cp .env.example .env.local
```

Add a restricted development key:

```env
GEMINI_API_KEY=your_development_key
```

Run locally:

```bash
npm run dev
```

Quality commands:

```bash
npm audit --omit=dev --audit-level=high
npm run typecheck
npm run build
npm run preview
```

GitHub Actions uses the same lockfile with `npm ci`, runs the production dependency audit, type-checks the project, and creates a production build. The current validated production audit reports no vulnerabilities at the configured high-severity threshold.

## Reliability improvements

The recruiter-readiness pass adds:

- lazy Gemini initialisation so missing configuration produces a clear UI error
- on-demand loading of the Gemini service instead of placing the AI SDK in the initial application bundle
- retry controls for target generation and feedback analysis
- removal of silent fallback targets and fabricated low-score analysis objects
- validation and clamping of structured model responses
- input trimming and a 5,000-character session-note limit
- collision-resistant target identifiers when supported
- clearer accessibility labels and pressed states
- a checked-in npm lockfile for reproducible installs
- automated production dependency auditing, TypeScript checking and production-build validation

## Bundle behaviour

The AI service is loaded only when target generation or feedback analysis needs it. In the current validated production build, the initial application JavaScript is about 343 kB (109 kB gzip) and the on-demand Gemini-service chunk is about 295 kB (59 kB gzip). No generated JavaScript chunk exceeds Vite's default 500 kB warning threshold.

This is a performance boundary only. Lazy-loading the SDK does not make a browser-delivered API credential secret.

## Honest product boundaries

- The target exists in client memory and is only hidden from the visible interface; it is not cryptographically sealed.
- The displayed randomness marker is a client-generated session value, not verified entropy.
- Only the self-paced solo flow is currently implemented. Timed, tournament, leaderboard, and collaborative mechanics are not presented as working features.
- There is no account system, persistent session history, multi-user synchronisation, leaderboard, or research-grade experiment protocol.
- Gemini output can be incomplete or incorrect and should be treated as generated reflective feedback.

## Important deployment limitation

The current Vite configuration injects `GEMINI_API_KEY` into browser-delivered JavaScript when the AI chunk is loaded. Keeping `.env.local` out of Git prevents accidental repository exposure, but it does not keep the key secret in a deployed client.

Before public deployment, move target generation and analysis behind a server-side or serverless endpoint that stores credentials outside the browser, validates payloads, applies rate limits, restricts model operations, and avoids retaining sensitive user text.

Until that architecture is implemented, use a tightly restricted development key and present this repository as an experimental browser client rather than a secure public AI service.
